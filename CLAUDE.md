# CLAUDE.md

Finds the cheapest **member** price for TOP 10 Holiday Parks stays. Member price only; ignore public/non-member pricing.

## Layout (pnpm monorepo)
- `packages/core/`: `@top10/core`. All logic lives here: `poll`, `deals`, `leadProfile`, `history`, `syncCatalog`, `loadCatalog`. Put new logic here.
- `packages/core/src/types.ts`: shared data shapes. Keep it free of Node-only imports, because the web app imports it.
- `apps/cli/`, `apps/api/`: thin wrappers over `@top10/core`. Don't duplicate logic in them.
- `apps/web/`: React + Vite. Fetches from the API on page load. No logic beyond display and filtering.
- `data/config.json`: tracked rooms, nights, horizon, throttle.
- `data/catalog.json`: park/room names and images, generated by `cli sync`.
- `data/prices.db`: disposable. Delete and re-poll if the schema changes.
- `docs/api-notes.md`: API endpoints and quirks. Read before touching `client.ts`.

## Commands (run from repo root)
- `pnpm run cli -- sync | poll | deals [from] [to] | lead | history <roomId> <date>`
- `pnpm run api`: JSON API on 127.0.0.1:3000
- `pnpm run web`: web app on :5173 (proxies /api to the API)
- `pnpm run typecheck`

Use pnpm (the repo has `pnpm-lock.yaml`).

## Rules
- Read-only against the site. Never call booking endpoints.
- Keep request volume low; respect `requestsPerSecond`.
- Never print or commit `.env` or raw API responses (they contain the member email).
- Run `pnpm run typecheck` after code changes.
